Validation workbench and ownership contract
=========================================

The validation files are separate from the immutable submission_04 runner. No historical numeric score enters promotion. Control and candidate predictions must contain exactly the same evaluated Source 1 IDs, including entities with zero predictions.

`decision_policy_v2.decide_v2(frame, claims, config)` returns `(chosen, ownership_lost, diagnostics)`. `diagnostics` contains aligned row information and a global summary. The complete claims table needs pair keys (`source1_entity_id`, `candidate_entity_id`), `probability`, recorded `candidate_order`, and optional boolean `gate_veto` and string `gate_reason`. Normal claims meet `t_rest`; one original top candidate can qualify as a rescue at `t_first`. Proposals are formed before vetoes and arbitration. Losing or vetoed candidates do not cause a second rescue. All eligible claims, including rescues, compete for each target. Equal scores abstain. A positive `ownership_margin` or `ownership_min_score` can also produce no owner. Street agreement never forces an owner. Target ownership is exclusive; one Source 1 may own many targets.

`evaluate_sprint.decide_control` reproduces the immutable runner's original decision function without importing scoring dependencies. The tests extract that function's AST directly and check exact control parity across 30 collision/rescue fixtures. This retains the original tie/rescue behavior for the control.

`export_sprint_workbench.py` consumes original score chunks, their checksum markers, and an immutable ordered reference list. It verifies each chunk's reference slice hash, including zero-candidate references, and its parquet hash. It exports pair keys, stage-one and stage-two scores, final probability, source, country, original candidate order, and explicit unevaluated decision state. Truth is never opened. The reference list must follow actual scoring task order; OOF regrouping requires the grouped scoring order. Complete lineage needs input, normalization, aliases, indexes, native library, feature schema, and model hashes. This export does not reconstruct missing feature matrices.

`evaluate_sprint.py` consumes separate truth/control/candidate JSON maps, ordered reference records, and a claimant-universe manifest. Prediction/truth values must be target-ID lists, not nested legacy records. Use `--confirmation` for a single cohort-locked confirmation; otherwise the non-audit role is development. It reports paired entity macro F0.5 changes and bootstrap intervals, per-country deltas, precision, singleton false predictions, newly empty non-singletons, and true/false links removed. Gate non-inferiority needs a paired lower bound above -0.0005, precision not falling, singleton false predictions not rising, and no country point loss below -0.0005. Improvement additionally needs the lower bound above zero. No historical absolute singleton limit is used. Ownership promotion additionally needs `kind="complete_heldout"`, `complete=true`, and `supervised_training_excluded=true` in the scored-universe evidence. Exact-key rivals are explicitly insufficient. Even a complete declared heldout universe differs from official-test density.

For an audit, the evaluator verifies `candidate_frozen` status, timezone-aware `frozen_at`, parent freeze hash, split ledger hash, exact audit reference-file hash (`audit_sampled_ids_sha256`), and nonempty code/model/schema/index/native hash groups. It then creates an exclusive audit-start lock beside the reserved reference file before opening truth. An alternative report directory cannot repeat the same audit.

`reserve_splits.py scan` projects reference ID columns from experiment parquets and collects IDs from prior reference/truth/error JSON, TSV/CSV, text logs, and string ID arrays. Numeric array headers are inspected without reading labels/features. Raw split definitions, owner lookup databases, indexes, and alias statistics do not make every raw dataset member exposed. All local and remote artifacts must be accounted for before `reserve --scope-reviewed` is used. Reservation takes two disjoint deterministic 10k samples from previously unexposed outer holdout references; no target labels are read. New reserved audit data must never be fed back into the exposure scanner or tuning.

Use `local_exposure_v3`, not the first scan (`local_exposure_20260927`), which incorrectly treated raw split manifests as exposure and is retained only as correction evidence. The completed VM1 JSON/parquet scan contributed 51,825 IDs beyond local experiment exposure. VM2's complete hash/projected scan contributed no new IDs. The additional `local_output_exposure` ledger accounts for all 1,732,544 prior full-submission Source1 IDs and verifies matching/candidate ID order. The scope-reviewed `merged_exposure` ledger contains 2,339,992 IDs. These immutable prior-exposure inputs were used to reserve disjoint confirmation and audit samples of 10,000 references each at 07:48:42 UTC; no fresh labels have been read. `fresh_splits/plan.json` binds the cohort and exposure fingerprints. The complete outer-heldout reference universe has 331,012 entities, including exposed references retained only as unlabeled competitors. Reserved inputs and exposure metadata were uploaded and hash-checked on both machines.

`development_labels` contains only the already-exposed selected 20k tune owners (69,137 supplied true targets). Target text comes from normalized indexes and does not preserve punctuation/case; the manifest marks this explicitly. Raw target ablations must recover the same target IDs from supplied raw training TSVs. The dedicated exporter refuses unexposed IDs and all outer-holdout IDs. It supplies natural labeled collision cases to the gate lane; it contains no fresh confirmation/audit labels.

The original bridge development candidate/context feature tables are absent locally. Saved first-stage, second-stage, and OOF boosters survive. The 250-reference incumbent replay has identical stored second-stage probabilities (`max_difference=0`), but missing original pair keys prevent that numeric array from independently proving candidate-ID parity. Rebuild current candidates using the frozen pipeline rather than joining probabilities to older pre-bridge caches by length.

`evaluate_ownership_fixed.py` performs the predeclared ownership-v2 margin-zero ablation on the sealed current development50k graph and scores only the same already-exposed selected20k truth. It verifies the frozen control, workbench pair IDs/order and hash, processed-reference coverage including empty references, and parity/asset proof hashes. It saves both prediction maps, paired metrics, per-entity link changes, and changed-pair decisions. This is a complete declared development graph, with the full first-stage model and outer-training second stage, rather than a heldout ownership density test. It cannot certify promotion. Learned residual comparisons must instead recompute both policies on the same early10k plus selection20k graph, excluding the residual-fit20k references. No historical numeric score subtraction is allowed.

Fresh evaluation requires prediction evidence that binds the candidate/control/reference/universe hashes, a verified reservation plan, and a prior candidate selection. Final audit additionally requires the exact frozen decision configuration, sufficient measured release budget, and a cohort-anchored once-only evaluation lock. Development quality and runtime evidence remain separate; synthetic mechanism timings are never a full-test runtime estimate.

`heldout_scoring_evidence.json` now certifies the sealed complete heldout graph: 331,012 declared and processed references, 1,325 independently checked chunk reference slices, 13,240,480 pair keys, and zero zero-candidate references. The original raw reference records, frozen control, parity/asset proofs, complete pair file and pair order are hash-bound. No owner labels were opened. `heldout_incumbent_predictions` caches the original native decision function extracted from the pinned runner, with every reference including 19,692 empty predictions. It has 1,094,049 accepted links and separate reserved-cohort baseline maps. All six files are byte-identical on VM1, Mac and VM2, as recorded in `heldout_incumbent_transfer.json`. Ownership v2 changes five unlabeled reference predictions; none belongs to either reserved fresh cohort. These counts are mechanical evidence only.

`learned30k_independent_grid` contains independently replayed paired checks for the three predeclared weights .50, .75 and 1.0. All regress on the same selected20k labels and none has a positive paired lower bound. `adapter_v1_early10k_independent` contains the separately authorized anchored-adapter pilot, measured only on early10k stopping labels with all30k claimants. Its +0.00007408 point gain has interval [-0.00022806, +0.00038575]; it removes 85 true links and 33 false links, and recall falls by 0.00244618. The pilot is tuning evidence. No selected20k adapter metric or fresh-label evaluation was performed. Persisted raw model corrections and additive incumbent-logit inference were independently reconstructed exactly; `anchored_adapter_semantics_probe.json` records the native LightGBM offset behavior.
