## Remaining work

### 1. Preserve strings in the generic loader

File: `code/business_entity_resolution/src/data/loader.py`, lines 35–85.

`load_tsv()` still defaults to `dtype=None`, despite its documentation promising string preservation. The generic `load_dataset()` inherits this behavior.

Reproduction: a TSV containing business name `007` and address `00123` loads those fields as integers `7` and `123`. The typed source loaders are unaffected because they explicitly pass string dtypes.

Required change: make the generic default preserve strings, with type inference available only as an explicit option. Add a test covering both generic entry points.

### 2. Make submission validation reject malformed input

File: `utils/validate_submission.py`.

Reproduced cases returning an empty error list:

- A data row containing only `S1-A`, with no tab and no second field, in both output files.
- A match list containing `,S2-A,,`, which silently discards empty ID tokens.
- A nonexistent `S2-ghost` in both files when the supplied Source 2 ID set is empty. Membership checks are skipped because they use the set's truth value.

Required changes:

- Require exactly two fields per physical data row; an empty list must still have its tab separator.
- Reject malformed nonempty ID lists rather than repairing them during validation.
- Check membership unconditionally once the target ID sets are available. Distinguish `None` from an empty set.
- Use the organizer validator as the final submission gate when it is available. This implementation is a custom pandas-based validator; it is not the stdlib-only helper described by the organizer.
- Stream the output rows or use a disk-backed comparison for the subset check. The current implementation holds both DataFrames and both parsed maps in memory. Full-scale peak memory and runtime have not been measured.

### 3. Wire cross-file integrity checks into the EDA run

Files: `scripts/run_eda.py` and `code/business_entity_resolution/src/data/schema.py`.

The new validation functions exist, but the EDA runner never invokes them or saves their outcomes. It also skips missing files and can still emit a report.

Reproduction: ground truth with `S1-A → S2-A` and `S1-B → S2-A` returns no contract issues. Cross-S1 ownership checking requested in the original review is still absent.

Required changes:

- Fail an official full-data run if a required file is missing; allow partial inspection only through an explicit mode.
- Execute and persist S1/ground-truth set equality, target existence, prefixes, duplicates, and target ownership checks.
- Report ambiguous target ownership as an integrity diagnostic. Do not silently impose exclusivity in the matcher before checking the actual labels.
- Implement these checks using ID columns, streaming, or a disk-backed store rather than requiring every business table in memory.

### 4. Regenerate measured reports

Files: `reports/eda/eda_profile_results.json`, `reports/eda/EDA_REPORT.md`, `scripts/build_notebook.py`, and `notebooks/01_eda.ipynb`.

The committed JSON has neither the new `sampling_metadata` nor `median_calculation_method` fields. Its measurements have not been regenerated by the changed profiler. The report relabels existing duplicate percentages as 50,000-row reservoir estimates, but the profiler does not calculate or emit those duplicate-name/address percentages.

Notebook tables now read JSON, but several narrative cells still hard-code measurements and a passed-contract verdict.

Required change: rerun the updated profiler, calculate every published duplicate statistic or remove it, persist validation outcomes and code provenance, then regenerate both the report and notebook from those results. Keep unmeasured checks explicitly marked pending.
